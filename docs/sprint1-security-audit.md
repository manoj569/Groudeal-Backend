# Sprint 1 backend security and correctness audit

Audit date: 1 November 2026. Scope: the actual .NET 9 modular monolith in this workspace. No payments, wallets, escrow, delivery, vehicle/property workflows, architecture rewrite, push or deployment were introduced.

## Verdict

**Conditional GO for Sprint 2 development; NO-GO for production.** Two confirmed High application defects were corrected with focused changes and regression coverage. No Critical defect was confirmed. Production requires a supported, patched runtime, verified deployment configuration, operator security controls and the operational checks below. Passing tests do not establish production readiness.

## Evidence and scope

Inspected README.md; docs/verification.md, security-model.md, database-design.md, group-buying-state-machine.md, architecture.md, api-contracts.md and local-development.md; all production C# source; both test suites; project/tool/SDK configuration; InitialCreate migration, designer, model snapshot and schema.sql; settings, Compose and startup script. There is no Git repository at the supplied root, so Git status/diff/history could not establish a clean baseline. Previous verification claims are historical evidence, not results of this audit.

Paths below are repository-relative. Findings identify the relevant method or configuration section. Severity describes impact in the current non-financial reservation service.

## Coverage of requested audit areas

1. **Authentication:** Identity hashes passwords; minimum 12 and maximum 128, lockout after five failures. Login checks active domain account; every JWT request checks active profile and token version. Explicit issuer, audience, lifetime, signature and HS256 allowlist; 15-second skew; default 15-minute expiry bounded 1–60. No committed signing key, database password or demo password. H1 corrected role revocation. Tests cover suspended-account login/token rejection and invalid JWT expiry/issuer/audience/signature/algorithm. Account lockout is a login throttle, not administrative suspension.
2. **All endpoint authorization:** public register/login and catalog reads are intentional. /auth/me and logout require authentication. Seller profile creation/update and dashboard require authentication plus owner lookup; onboarding intentionally does not require Seller. Product/campaign create/update/submit/transition require Seller plus owned, approved active seller; product/campaign IDs are owner-checked, pickup ownership is checked. Reservations/list/cancel require Customer and cancellation/list constrain customer ID. Every /admin route requires Admin and service-level Admin check. Non-development OpenAPI requires Admin. No role/status/price injection inputs were found; unmapped JSON is rejected. H2 corrected approval checks after lock wait.
3. **Transactions, capacity, idempotency:** real PostgreSQL READ COMMITTED transactions; seller FOR SHARE then campaign FOR UPDATE serializes capacity changes and approval edits. Cancellation/expiry take only campaign lock, with no inverse seller lock. Unique campaign/customer/key index prevents duplicate retry insertion; retry quantity mismatch returns 409; keys persist after terminal reservation states. Same-key replay intentionally precedes eligibility/time checks and cannot create a new commitment. No aggregate overbooking path was found through HTTP.
4. **Races:** target completion and reservations share the campaign lock; cancellation can reopen TargetReached only before deadline and before confirmation seals it. Expiry rechecks state/time after locking. Cancellation/confirmation race coverage checks both possible serial outcomes and capacity invariants. Existing tests cover 20 competing joins and parallel identical keys. Cancellation-versus-new-reservation, cancellation-versus-expiry, multiple workers, process kill during commit and long-running lock/load stress are not exhaustively tested; do not infer those guarantees solely from the suite.
5. **State machine:** drafts only editable; Admin cannot skip review edges; sellers cannot arbitrarily set approval/capacity/status. Confirmation precedes fulfillment/completion. Failed marks active reservations Expired and resets quantity atomically; Completed marks them Completed and retains historical filled quantity. Terminal states cannot reopen. M4 is an unresolved policy/liveness gap, not an accidental acquisition-expiry defect.
6. **Worker:** deadlines and states persist in PostgreSQL; each row transaction atomically updates campaign, reservations and audit. Repeated expiry processing does not duplicate audit. Scoped processor is recreated after batch failure; no in-memory cursor is required for restart. Scheduled opening/expiry may lag polling/backlog; M3 and L6 remain.
7. **Schema:** migration and model agree; numeric(18,2) money, numeric(18,3) quantities, numeric(10,7) coordinates; timestamptz timestamps; campaign xmin concurrency token. Restrict deletes, identity/profile and customer/campaign FKs, composite seller/location FK, unique normalized email, SKU, seller/slug and scoped idempotency; indexes cover expiry, customer history and campaign reservation status. Positive price/quantity, price ordering, dates, capacity/min/max and rounded snapshot-total checks exist. M7 records defense-in-depth gaps. Maximum API price × quantity fits numeric(18,2).
8. **Prices and units:** sellers propose reference/group INR price per variant unit, Admin approves the immutable published campaign. No independent product base price or verified historical reference-price source exists; advertised discount truth is an Admin-review responsibility. Group price must be positive and <= reference. Reservation unit/total snapshots come exclusively from the stored campaign and round away from zero to two decimals, matching PostgreSQL positive-value round. A 5 kg variant reserved at quantity 2 means two variant units, not 2 kg. Campaign-referenced variants cannot be edited via SaveProduct. No payments or financial guarantees exist.
9. **Seller/public data:** profile edits reset approval and public eligibility. Public DTOs omit owner/customer IDs, contact details, FSSAI, review metadata and coordinates; active pickup addresses are intentionally public. Draft/pending campaigns are hidden; terminal campaign summaries remain public by current policy. M5 requires operator eligibility semantics; no confirmed private-field HTTP disclosure found.
10. **HTTP security:** body limit 64 KiB, CORS allowlist, no credential cookies, rate limits, HTTPS/HSTS outside Development, no-store/nosniff/CSP/referrer headers, generic Problem Details, no EF sensitive-data logging enabled. Logging does not deliberately include passwords/tokens/bodies. M6 and L6 remain; real TLS/proxy and high-volume abuse not verified.
11. **Contracts:** typed DTOs; bounded page size 100/page 100000; stable ID tie-breakers; validation bounds names/attributes, quantities, money, enums and UTC offsets. M2/L2/L3 record concrete gaps. Counts/items can differ across concurrent writes under READ COMMITTED; there is no consistent snapshot pagination promise.
12. **Seed/production:** explicit --seed-demo command is rejected outside Development; no automatic migration/seed on API startup. Seed is transactional and repeatable in ordinary use. Production provisioning is an operator task. L5 records helper hardening; deployment must never enable Development to seed production.
13. **Dependencies/.NET 10:** advisory audit includes transitive packages and the explicit SSH.NET override. No .NET 10 SDK is installed; no .NET 10 build was claimed. See M1 and verification below.
14. **Compose:** loopback-only published PostgreSQL port, required external password, persistent volume and bounded pg_isready healthcheck; no volume deletion performed. Static Compose configuration validates. No Docker engine was reachable; image startup, health behavior and Testcontainers path were not verified.

## Changes made

- src/GroupBuy.API/Program.cs: validate current role memberships during JWT authentication (H1).
- src/GroupBuy.Infrastructure/Marketplace.cs: refresh tracked seller values while holding its acquired row lock (H2).
- tests/GroupBuy.IntegrationTests/BackendTests.cs: regression tests for both fixes, suspension/JWT validation, cancellation/confirmation race and failed fulfillment.
- docs/sprint1-security-audit.md: this audit, findings, evidence and release verdict.

No schema or domain-policy changes were necessary for the two High fixes. The extra role lookup adds one database query per authenticated request; measure its cost before scaling. Database unavailability fails authentication processing closed rather than permitting stale privileges. Seller reload adds a query within the existing transaction and lock lifetime.

## Verification

Commands use a workspace-local DOTNET_CLI_HOME and disable shared compilation where needed because the default sandbox build/test process communication was unreliable. Earlier unsuccessful attempts are not counted as successful validation.

- SDK 9.0.302 / runtime 9.0.7 observed. dotnet --info partially failed accessing Windows Service Control Manager; installed SDK/runtime lists were still printed.
- NuGet advisory audit initially failed sandbox DNS; rerun with network access succeeded: **no vulnerable packages reported across all six projects** by configured NuGet sources. This does not assert absence of unknown vulnerabilities or certify the installed runtime.
- Docker engine unavailable: missing dockerDesktopLinuxEngine named pipe. docker compose config --quiet succeeded with a temporary placeholder password; Compose runtime and Testcontainers path remain **unverified**.
- Isolated PostgreSQL 17.6 initialized inside ignored .local/audit-postgres, listening only on 127.0.0.1:55433; existing server/data directories were not reused. The test fixture creates/drops a random database and applies checked-in migrations.
- EF tool restored at pinned 9.0.11. has-pending-model-changes: **no model changes**. Idempotent migration script generated into ignored .local/audit-migrations.sql.
- Final solution build: **succeeded, zero warnings/errors**. An earlier added test used an analyzer-disallowed assertion form; corrected before the final build and test run.
- Final `dotnet test GroupBuy.sln --no-restore -m:1 -p:UseSharedCompilation=false`: **21 unit tests passed, 13 PostgreSQL integration tests passed, zero failures/skips**. Five integration tests were added. Results: tests/GroupBuy.UnitTests/TestResults/audit-results.trx and tests/GroupBuy.IntegrationTests/TestResults/audit-results.trx (ignored artifacts).
- Initial separate-session PostgreSQL attempt could not be reached by the elevated runner and integration fixture setup failed; this was an infrastructure failure, not a pass. Final verification started PostgreSQL and tests together in one elevated session and stopped the server in a finally block. Fresh-database migration application and fixture cleanup succeeded on that run. PostgreSQL shutdown was confirmed.
