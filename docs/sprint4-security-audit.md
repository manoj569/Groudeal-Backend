## Verified controls and evidence boundaries

JWT validates issuer/audience/signature/HS256/lifetime with 15-second skew and bounded lifetime; every authenticated request checks active profile, token version and current roles. Expired/wrongly signed/wrong issuer/audience/algorithm tokens and removed-role/suspended-account tokens are regression-tested. Secrets are externally configured with a minimum length, not committed defaults. Test fixtures generate ephemeral signing/password values. Actual Production startup probes reject --seed-demo and an undersized JWT key before database access (.local/sprint4-startup-guards.json). Secret entropy/rotation/sink policy at a real host remains unverified.

Public registration rejects extra role fields and grants Customer only. Admin routes and application methods both require Admin. Seller writes refresh approved ownership under seller locks. Product publication/status guards preserve active campaign holds; cross-owner resources return 404. Customer reservations/pickups/notifications are owner scoped. Public seller projections omit contact/FSSAI/private identity. Admin governance omits customer identity and pickup code/hash, and filters audit metadata. Pickup plaintext is returned only by explicit owner POST with no-store; codes are high-entropy, hashed, time limited, rate limited, single use with persisted failure lockout.

Reservation capacity and idempotency use campaign row locks and a scoped unique key. Price snapshots are computed server-side. Seller->campaign->pickup lock order is consistent in fulfillment; cancellation locks campaign and closes at target. Fulfillment consumes physical stock only on successful collection, retains terminal snapshots and completes only after every pickup is collected. Notifications/audits share the transaction, with unique notification delivery keys. Failure-trigger tests prove rollback, backoff persistence, independent candidate progress and recovery in a new host; cancellation propagates without partial writes. These do not cover every OS crash.

Input limits, decimal/unit validation, foreign keys/check constraints and indexes are enforced by application and PostgreSQL tests. Raw SQL uses parameterized identifiers/values in application workflows; test-only generated role/database names are fixed-prefix GUIDs. Exception responses expose safe Problem Details, not SQL/stack traces; application error logs record type/trace, not bodies/secrets. Production proxy and sink redaction were not inspected. In-memory tokens/private caches are cleared on 401/logout, offline private views are blocked and PWA tests inspect API exclusions. No payment workflows were added.

## Dependency and runtime verification

NuGet vulnerability query succeeded after sandbox DNS retry, reporting no vulnerable packages across six projects from configured sources. npm required NODE_OPTIONS=--use-system-ca to trust the Windows certificate store; TLS verification was never disabled. Production npm graph: zero findings; full graph: 20 development-tooling findings. Counts are affected package entries, not 20 independent exploits. Unknown vulnerabilities, shared runtimes and container images are outside these package checks.

[Microsoft support policy](https://dotnet.microsoft.com/en-us/platform/support/policy/dotnet-core) and [official .NET 8/9 end-of-support notice](https://devblogs.microsoft.com/dotnet/dotnet-8-9-end-of-support/) were checked during this sprint. Installed runtime remains 9.0.7. [PostgreSQL version policy](https://www.postgresql.org/support/versioning/) recommends current minor releases; tested portable 17.6 proves compatibility only and is not an approved production patch baseline. Pin/review current supported image digests and scan them before release.

## Verdict

NO-GO for a live controlled pilot until High gates and environment acceptance evidence are closed. GO for continued isolated development/staging verification with synthetic data. No deployment, push, production account grant or legacy backfill was performed.
